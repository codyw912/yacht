# Yacht 0.13: Reproducible Task Sampling

**Source:** plane:YACHT-5

Status: implemented; release candidate on `release-0.13.0` passes every token-free gate and awaits the live provider release gate. Slices 1–3 are complete.

## Release outcome

Yacht 0.13 can select a bounded random sample from an explicit Course task
population without making the result depend on source ordering, process state,
or a language runtime's pseudorandom-number implementation. The resulting
Course handoff records the exact selected tasks and the provenance needed to
recompute and audit the selection.

## Why this release

Yacht already supports explicit benchmark instance IDs, reusable task-set
files, and an ordered `max_instances` cap. That is enough for fixed smoke sets,
but not for reproducible sampling across a larger population. The roadmap names
seeded task sampling as the remaining gap in both generalized benchmark
selection and repeated-run quality.

Yacht 0.12 made the Logbook a portable run-state interface. Sampling can now be
added without creating another filename convention: the Course handoff remains
the durable description of the selected Course, and the Logbook indexes that
artifact.

## Release invariants

1. **Ordered selection stays unchanged.** Omitting random selection preserves
   the current ordered `max_instances` behavior.
2. **Random selection is explicit.** It requires an explicit task population, a
   positive `max_instances`, and a non-negative integer seed before preflight or
   task execution.
3. **Selection is runtime-independent.** Yacht does not use Python's global RNG
   or promise the behavior of a runtime-specific sampling function.
4. **Source order is not evidence.** Reordering the same unique task IDs does
   not change the population digest or selected IDs.
5. **The handoff records facts.** Exact selected task IDs remain the execution
   contract. Selection metadata explains how Yacht derived them.
6. **No implicit dataset enumeration.** This release samples IDs declared in
   the Regatta or its task-set files; it does not download a whole dataset to
   discover a population.

## Canonical selection contract

The algorithm identifier is `sha256-rank-v1`.

`LP(value)` means the eight-byte unsigned big-endian length of `value`, followed
by the bytes of `value`. Text fields are UTF-8. Integer text is canonical ASCII
decimal with no sign or leading zeroes, except that zero is `0`.

For task ID `id` and seed `seed`, the ranking preimage is:

```text
LP("yacht.instance-selection.rank.v1")
|| LP(decimal(seed))
|| LP(id)
```

The rank is the raw SHA-256 digest of this preimage. Tasks sort by rank bytes,
then by task-ID UTF-8 bytes as a collision tiebreaker. The first
`max_instances` tasks are selected and remain in that rank order.

The population digest preimage is:

```text
LP("yacht.instance-selection.population.v1")
|| LP(decimal(population_count))
|| LP(id_1)
|| ...
|| LP(id_n)
```

`id_1` through `id_n` are the unique population IDs sorted by UTF-8 bytes. The
recorded value is `sha256:` followed by the lowercase hexadecimal SHA-256
digest. This makes the digest independent of source-file ordering and gives
other languages an exact byte contract.

## Slice 1 — Selection contract and pure selector

### Changes

- Add the random-selection config contract under `course.adapter.selection`.
- Require `method = "random"`, an explicit seed, and `max_instances`.
- Implement the canonical ranking and population digest as pure functions.
- Reject duplicate IDs and samples larger than the declared population.

### Acceptance

- Fixed cross-language test vectors pin the canonical bytes and digests.
- Reordered populations produce the same digest and selected IDs.
- Different seeds produce independently deterministic selections.
- Invalid selection configuration fails as `ConfigError` before preflight.

## Slice 2 — Loader integration and durable provenance

### Changes

- Apply selection after task and instance-file expansion and before the domain
  Course is constructed.
- Preserve selected task order through plans, runbooks, attempts, and grading.
- Record method, algorithm, seed, requested size, population count, and
  population digest in the Course adapter handoff.
- Keep exact selected IDs in the handoff's task list and adapter instance list
  where the adapter already uses one.

### Acceptance

- Repeated config loads select identical tasks.
- Reordering an instance file does not change the resulting handoff.
- Handoff validation accepts complete provenance and rejects malformed fields.
- Ordered `max_instances` fixtures remain byte-for-byte unchanged.

## Slice 3 — Public workflow and release proof

### Changes

- Document the random-selection configuration and its reproducibility boundary.
- Add a token-free example or smoke scenario that writes and reloads a sampled
  Course handoff.
- Rebaseline the roadmap after the release proof passes.

### Acceptance

- A user can configure a seeded sample without knowing Yacht internals.
- The public CLI produces the same selected tasks and population digest on two
  independent runs.
- Focused tests, the full suite, formatting, lint, and compile checks pass.

## Non-goals

- Named benchmark sampling presets.
- Automatic enumeration of remote benchmark datasets.
- Stratified, weighted, or replacement sampling.
- Statistical changes to aggregate reports.
- Parallel task execution.
- Report-navigation redesign.
