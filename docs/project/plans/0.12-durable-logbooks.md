# Yacht 0.12: Durable Logbooks

**Source:** plane:YACHT-4

Status: implemented for Yacht 0.12.0.
Slices 1–6 are complete.

## Release outcome

Yacht 0.12 makes the Logbook the authoritative, portable interface to a
Regatta's persisted state. A user or external tool should be able to open one
run index, identify the Regatta and Course, see its current status, and locate
its Wake and Scorecards without knowing Yacht's internal filenames.

The index locates and describes artifacts; it does not replace them. Scorecards
remain the comparison summary, and the Wake remains the auditable evidence.

## Why this release

Yacht 0.11 added enough first-class harness coverage for the near term. The
higher-leverage work is making the evidence those harnesses produce durable and
simple to consume.

The current implementation is only halfway there:

- `yacht.logbook.index` writes `run-index.json`, but exposes little more than a
  writer and `read_run_kind()`.
- Benchmark status prefers the index, while smoke status, report dispatch,
  latest-Logbook selection, and `yacht serve` still reconstruct state by
  probing well-known filenames.
- Benchmark and smoke workflows write the index at the end. A blocked or failed
  Regatta can therefore leave useful Wake without an index describing it.
- ADR 0005 says public JSON Schemas are the primary structural contract, but
  runtime validation still mirrors them by hand and the released wheel does not
  contain the schema files.
- Known contract drift proves the duplication is active risk: the Wake schema
  omits `metrics.usage_source`, which Yacht can emit, while the run-index schema
  requires a non-empty comparison list that the Python validator explicitly
  permits to be empty.

The architecture goal is a deeper Logbook module: a small interface for
validated discovery and artifact resolution, with schema loading, compatibility,
path safety, and error normalization behind the seam.

## Release invariants

1. **Artifacts remain the source of truth.** The index points to Wake and
   Scorecards; consumers still validate those artifacts before interpreting
   them.
2. **A valid current index is authoritative.** Consumers do not silently replace
   its identity or status with filename guesses.
3. **Absence means legacy; invalidity means broken.** A Logbook without an index
   uses the existing discovery path. A malformed index is reported as an error,
   not silently treated as absent.
4. **New index paths are portable and rooted.** Moving a complete Logbook keeps
   it readable. Artifact references cannot escape the Logbook directory.
5. **Historical Logbooks remain readable.** Yacht reads the v1 index and
   scorecard-only Logbooks, but writes only the new contract after cutover.
6. **Schemas own structure.** Existing Python validator functions remain the
   call-site interface and preserve `SchemaValidationError` / `ConfigError`
   ergonomics; Python retains semantic and cross-artifact checks only.
7. **The dashboard remains local and read-only.** Per-request disk reads,
   visibly broken artifacts, and deletion-based removal remain as decided in
   ADR 0010.
8. **Generated Logbook artifacts and exports are distinct.** Reports owned by a
   Logbook may be indexed. User-selected output outside the Logbook remains an
   export and is not made part of the portable Wake.

## Slice 1 — Ship executable schema contracts

### Goal

Establish one production schema-loading path before the run index depends on
it.

### Changes

- Include one canonical copy of the public schema files in both source checkouts
  and built wheels. Do not maintain a package copy and repository copy by hand.
- Select a maintained Draft 2020-12 validator. Do not implement a Yacht-specific
  JSON Schema subset.
- Add cached schema loading and normalize engine failures behind the existing
  validator interface.
- Use the Wake as the pilot artifact because its validator is self-contained
  and all writes already pass through `validate_wake_document()`.
- Reconcile `metrics.usage_source` between the Wake schema and emitted model.
- Delete the Wake's duplicated handwritten structural checks; retain only
  semantic checks the schema cannot express clearly.

### Acceptance

- `validate_wake_document()` keeps its signature and project error type.
- Existing valid and invalid Wake tests retain their observable behavior.
- A wheel installed outside the repository can load the schema and validate a
  Wake.
- The wheel contains the same schema bytes used by source-checkout validation.
- No course, harness, or runtime module is imported by the schema loader.

### Non-goals

- Migrating every artifact family.
- Splitting handwritten validators into more handwritten modules.
- Changing Wake semantics beyond resolving existing schema drift.

## Slice 2 — Define and read the run-index v2 contract

### Goal

Create the durable contract that the rest of the release can trust.

### Changes

- Add a versioned run-index v2 schema rather than changing the meaning of v1 in
  place.
- Define Regatta identity, Course, run kind, lifecycle timestamps, status,
  comparisons, artifact inventory, and optional child-Logbook references for
  repetition collections.
- Store new artifact and child references relative to the Logbook.
- Add one validated Logbook reader that distinguishes current indexed,
  historical v1, legacy scorecard-only, and broken Logbooks.
- Resolve artifact paths through that reader and reject traversal or references
  outside the Logbook.
- Normalize safe v1 references for historical Logbooks; keep the v1 writer
  retired after cutover.
- Migrate `validate_run_index_document()` to schema-first validation while
  preserving its call-site interface and error normalization.

### Acceptance

- A current indexed Logbook yields validated identity, status, timestamps,
  comparisons, and resolved artifact references through one module.
- Moving the Logbook directory does not break current artifact references.
- `..` traversal and outside-root absolute references are rejected as broken.
- Existing v1 and scorecard-only fixtures remain readable.
- A malformed present index never falls through to legacy filename discovery.

### Non-goals

- Loading or interpreting Scorecard contents in the index reader.
- General artifact migration tooling.

## Slice 3 — Record the Regatta lifecycle

### Goal

Ensure the index describes partial and failed work, not only successful
completion.

### Changes

- Create the v2 index when a benchmark or smoke Regatta starts.
- Update it atomically at durable pipeline transitions: preflight, task
  attempts, launch, grading, Scorecard production, and terminal completion or
  failure.
- Register known artifact paths before execution and update their recorded
  presence as the workflow advances.
- Record started, updated, and terminal timestamps without inventing values for
  stages that did not run.
- Centralize workflow updates through the Logbook module rather than rebuilding
  the document in each workflow.

### Acceptance

- Interrupting or failing after preflight leaves a valid index with the actual
  terminal/non-terminal status and the Wake produced so far.
- Successful smoke and benchmark Regattas expose the same lifecycle vocabulary.
- Index writes are atomic; readers see the previous valid document or the next
  valid document, never a partial JSON file.
- Recorded artifact presence is a write-time fact. Status surfaces check current
  disk presence before claiming that an artifact is still available.

### Non-goals

- Resuming execution from the index.
- Turning every internal progress message into a persisted state.
- Changing comparison grading or benchmark execution order.

## Slice 4 — Cut status, report, and discovery over

### Goal

Remove duplicated run-state reconstruction from user-facing readers.

### Changes

- Route CLI run-kind detection, benchmark status, smoke status,
  latest-Logbook selection, and dashboard discovery through the Logbook reader.
- Resolve Scorecard and Wake paths from the artifact inventory when a current
  index exists; domain report modules continue to validate and interpret those
  artifacts.
- Keep explicit marker-based discovery only for Logbooks with no index.
- Make indexed identity and lifecycle status visible even when a Scorecard is
  missing.
- Preserve ADR 0010 behavior: invalid indexed Logbooks appear visibly broken in
  `yacht serve`, and deleting a Logbook removes it on the next request.

### Acceptance

- `yacht status --format json`, `yacht report`, and `yacht serve` agree on run
  kind, Regatta, Course, status, and artifact paths for the same Logbook.
- An indexed Logbook with a missing Scorecard is still discoverable and clearly
  reports the missing artifact.
- An invalid index produces a project error in the CLI and a broken entry in the
  dashboard.
- Historical v1 and scorecard-only Logbooks retain their current rendered
  behavior.
- User-facing consumers no longer carry their own current-index filename maps.

### Non-goals

- Merging status, report, and dashboard rendering into one renderer.
- Changing report statistics or visual design.
- Removing legacy discovery in this release.

## Slice 5 — Cover repetitions and generated reports

### Goal

Make the complete local evaluation collection discoverable, not only each leaf
Regatta.

### Changes

- Write a v2 index for a repetition parent and record child Logbooks with
  relative paths and statuses.
- Index the aggregate Scorecard and generated reports owned by the parent
  Logbook.
- Discover repetition parents and children without double-counting their
  vessel outcomes in collection views.
- Keep output written outside the Logbook classified as an export rather than
  part of the Wake.

### Acceptance

- Moving a repetition parent with its `runs/` tree preserves every child link.
- Status identifies incomplete children and the aggregate artifacts actually
  available.
- Dashboard discovery exposes the parent and reaches child evidence without
  counting the same attempt twice.
- A missing child is visible and does not invalidate unrelated children.

### Non-goals

- Cross-machine synchronization.
- Signed Logbooks or remote artifact URLs.
- New aggregation statistics.

## Slice 6 — Compatibility and release proof

### Goal

Prove the new seam from source checkout, installed wheel, partial execution,
and historical artifacts.

### Changes

- Add versioned fixtures for scorecard-only, v1 indexed, v2 partial, v2 complete,
  moved, malformed, and repetition Logbooks.
- Update schema and command references to describe authoritative-index and
  legacy behavior.
- Rebaseline the broad roadmap so shipped harness, Course, evaluator, and
  doctor work no longer appear as active gaps.
- Exercise the built wheel against a token-free smoke Regatta and inspect it
  through status, report, and dashboard paths.

### Acceptance

- The complete unit suite, formatting, coverage, and compile checks pass.
- The installed wheel validates packaged schemas without repository files.
- A token-free smoke produces a v2 index and all three user-facing readers agree
  on it.
- Historical fixtures stay readable and malformed current artifacts fail
  explicitly.
- The standard live release gate passes before publishing 0.12.0.

## Dependency order

```text
Slice 1: schema runtime and Wake pilot
    |
    v
Slice 2: run-index v2 contract and reader
    |
    v
Slice 3: lifecycle writer
    |
    v
Slice 4: consumer cutover
    |
    v
Slice 5: repetition collections
    |
    v
Slice 6: compatibility and release proof
```

Each slice is one focused pull request. A slice must leave `main` releasable;
consumer cutovers do not land before the reader and lifecycle writer they need.

## Deferred beyond 0.12

- Additional first-class harnesses.
- New Course or evaluator adapters.
- Broad Rigging method expansion; add one only when a concrete evaluation needs
  semantics Yacht does not already support.
- Plugin or entry-point discovery.
- A full-schema migration in one release.

## Release decision

The release is ready when a newly written Logbook is self-describing and
portable, partial failures remain inspectable, status/report/dashboard share one
run-state seam, repetition collections are indexed without double counting, and
historical Logbooks still render honestly.
